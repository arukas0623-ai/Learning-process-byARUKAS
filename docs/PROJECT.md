# 项目说明

## 一句话定义

这是一个让任意 Agent 执行长期、证据驱动、低上下文学习的可插拔 Skill 框架。

## 它解决什么问题

普通聊天把教学、答案、历史和评价混在同一个上下文里，容易重复消耗 Token，也容易把“我看过”误认为“我会了”。本项目把职责拆开：

- **Agent**：提出问题、要求主动回忆、用 Feynman 方式追问、指出误解、设计应用任务。
- **Core**：规定学习协议、评估标准、证据门槛和上下文边界。
- **Adapters**：接入不同教材、能力地图和复习调度器。
- **User Space**：保存用户自己的长期状态，不属于任何模型或平台。

## 项目目标

1. 让 Chat 只承载当前教学，State 承载长期记忆。
2. 把 Input、Recall、Validation、Application 组成可重复的 IRLA 循环。
3. 让一次错误停留在观察/假设层，经过验证后才能成为稳定能力证据。
4. 让 Recall 阶段看不到标准答案。
5. 用明确预算限制状态加载，避免递归读取所有日志和历史。
6. 允许更换 Agent、知识源、能力地图和 scheduler，而不重写 Core。

## 明确不做什么

- 不开发 Web UI、移动端或桌面平台。
- 不建立新的数据库、云账户或商业服务。
- 不自动生成整套课程、整本书或无限题库。
- 不用人格标签、学习风格或一次回答推断长期能力。
- 不把 APKM、Codex、Claude 或 mastery-loop 写死为 Core 依赖。

## 设计判断

最小可用框架优先于功能最多的系统。只增加能降低答案泄漏、证据污染或上下文失控的机制；其他需求先在实例中验证，再决定是否进入 Core。

## 适用场景

- 长期学习编程、数学、语言、工程和专业知识。
- 需要主动回忆、迁移任务、错因追踪和定期复测的个人学习。
- 希望在 Codex、Claude Code、本地模型之间迁移学习状态的用户。

## 不适用场景

- 单次解释、翻译、摘要或事实查询。
- 只想导出一套静态闪卡，不需要复习调度。
- 需要社交、积分、内容市场或课程售卖的平台。
