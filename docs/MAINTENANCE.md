# 维护、迁移与隐私

## 日常维护

- 每次会话结束更新短摘要，并记录 scheduler 的蒸馏时间。
- 每周或每两周合并重复题目、清理脱离能力地图的题目、检查薄弱节点。
- 不把完整聊天记录复制进长期状态；保留可定位证据路径即可。

## 备份

备份整个 User Space，而不是只备份 `learner.md`。至少包含目标、能力状态、题库状态、证据和预算文件。备份前确认没有把 API Key、私密凭据或不应公开的原始材料提交到 Git。

## 迁移

迁移到另一台机器或 Agent 时：

1. 复制 User Space。
2. 检查 `ability_map_refs`、evidence 路径和 scheduler 路径是否仍有效。
3. 运行预算检查与状态 validator。
4. 用 `due` 做一次只读 smoke check，不要直接开始正式学习。

绝对路径是当前个人实例的已知限制；可迁移部署应改用相对路径、稳定 ID 或实例配置文件。

## 版本策略

- Core 协议和 schema 的破坏性变化应提升主版本。
- Adapter 变化应记录兼容的接口版本。
- User State 迁移应提供旧字段到新字段的说明，不直接覆盖原始证据。

## 隐私和公开仓库

本仓库当前包含个人学习实例示例。公开前应检查 `learner.md`、日志、代码证据和绝对路径是否包含个人信息。删除公开数据前先备份本地 User Space；不要为了文档完整而公开不必要的原始聊天。

## 许可证

当前仓库尚未声明许可证。若要允许他人 Fork、修改或商业使用，应由仓库所有者明确选择并添加 LICENSE 文件；在此之前，公开可见不等于获得再利用许可。
