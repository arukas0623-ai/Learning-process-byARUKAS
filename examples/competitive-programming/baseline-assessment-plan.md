# Competitive Programming Baseline Assessment

这不是记忆测验，也不是固定课程表；它用于建立第一批可复核的能力证据。

## 诊断原则

- 不把“看过”“听过”当作掌握证据。
- 先观察程序状态和问题拆解，再判断是否需要补充概念。
- 每个结论都区分 Observation、Evidence、Hypothesis、Verification 和 Stable State。
- 单次答对或答错只记录为本次证据，不直接升级或降级长期能力。

## IRLA 诊断单元

### Input

给出一个短程序、最小问题或极少量背景材料，范围覆盖变量、条件、输入输出、循环和简单调试；记录材料来源、前置假设和待验证点。Input 只提供工作对象，不授予能力等级。

### Recall

关闭材料后，让学习者闭卷说明：程序会怎样执行、变量如何变化、输入输出是什么、为什么会走某条路径。只显示 Learner View，不提前显示答案、解法或评分标准。

### Learning Validation

围绕同一对象追问原因、边界、反例和执行顺序；检查是否只是复述术语。将回答中的事实、误解、未知点和需要验证的假设分开记录。

### Application

要求完成一个极小的实际任务，例如补全代码、修复一个 bug、写出伪代码或把自然语言任务拆成输入/输出/状态/步骤。重点观察能否独立把概念转成操作。

### Transfer

更换数据、边界、约束或表述，使用未见过的变式重新完成任务。Transfer 证据必须包含可复核的选择、边界处理和失败路径；不能用一次相似题的正确回答替代。

## 首次诊断维度

1. 程序思维：能否按执行顺序追踪状态，而不是只描述代码表面。
2. 变量与状态：能否说明赋值前后对象的变化及变化原因。
3. 问题拆解：能否明确输入、输出、约束、步骤和可验证中间结果。
4. 独立 Debug：能否从错误现象提出假设，用最小反例或观测验证。
5. 代码执行过程：能否预测分支、循环边界和函数调用的实际结果。

## 证据输出

每个诊断单元结束后，写入具体回答、代码、测试或会话日志引用；为下一次验证指定一个闭卷题、陌生变式、最小实验或可复现测试。没有足够证据时，状态保持 `UNKNOWN`。
